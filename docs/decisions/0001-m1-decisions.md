# 0001 — Decisions made while fixing M0 and building M1

Date: 2026-10-29. Nothing in the Architecture and tech stack table changed. These are choices inside it.

1. **Data model rebuilt to the spec.** The M0 schema had 13 tables with different names and fields. It now has the 28 tables from "Data model" (uuid v7 via `uuidv7`, `createdAt`, `updatedAt`, `projectId` on every child). The migration was regenerated as `0000_init.sql`; local databases from M0 must be reset (`docker compose down -v`).
2. **Extra columns beyond the spec's key fields**: `projects.pitchScript`, `projects.setupStep`; `event_specs.name`, `requiredTech`, `sourceHash` (EventSpec cache by source hash), `sourceQuotes`, `peopleNamed` (ethics guardrail input, never shown in personas), `droppedFields`, `confirmedAt`; `criteria.sourceQuote`; `repos.ref`, `visibility`, `fileCount`, `dependencies`; `step_maps.fallbackClipUrl`.
3. **EventSpec source quotes.** The spec's `EventSpec` schema has no quote fields, but the F3 acceptance check requires every field to quote its source. `EventSpecExtraction` extends `EventSpec` with `sourceQuotes` keyed by field path. `enforceEventSpecQuotes` (packages/shared) keeps a field only if its quote is a verbatim span of the source, so a model cannot invent a field.
4. **Meta Model API adapter** speaks chat completions (`POST {META_API_BASE_URL}/chat/completions`, bearer key). The sandbox that built M1 could not reach dev.meta.ai, so the base URL, model IDs and JSON mode (`META_RESPONSE_FORMAT`: json_schema, json_object or none) are left to `.env`. At worker startup it calls `{base}/models` and fails if a configured ID is missing; it skips the check if that endpoint does not exist.
5. **Mocked adapter.** With no `META_API_KEY`, `MODEL_MOCK=true`, or a Demo Mode project, prompts run their deterministic `mock()` (packages/ai/src/heuristics.ts). The heuristics only report what they can quote, so they pass the same enforcement as a real model reply.
6. **Embedding width**: `EMBED_DIM` defaults to 1024 and is fixed into the migration. Changing it means generating a new migration.
7. **Auth.js v5** (5.0.0-beta.32, the current v5 release) with JWT sessions and no adapter tables; the `users` row is upserted on sign-in. The GitHub token is sealed (AES-256-GCM, key derived from `AUTH_SECRET`) inside the encrypted session cookie and in job payloads, and never reaches the browser.
8. **GitHub scope**: OAuth Apps have no read-only scope for private repos (`repo` grants write). The app requests `read:user user:email` only, so private repos cannot be read yet. Reading private repos read-only needs a GitHub App with `contents: read`. **Needs a decision.**
9. **shadcn/ui components** in `apps/web/src/components/ui` were transcribed from the new-york v4 registry because the registry was unreachable from the build sandbox. Re-running `pnpm dlx shadcn@latest add <name>` overwrites them with generated copies. The Sidebar uses 16rem (256 px) and a 3.5rem (56 px) icon rail as the spec asks.
10. **Status text contrast.** The spec's 600-shade status colours on a 12% tint fall below 4.5:1 for text in light mode, so each status has a `-foreground` token (800 shade in light, 400 in dark) for chip text; the 600/400 colour stays on icons and tints.
11. **Rate limits** are an in-process token bucket per user and route (`apps/web/src/lib/server/rate-limit.ts`). Fine for one web node; move to Redis when there is more than one.
12. **Screens for later milestones** render the project and state which milestone ships them, rather than showing fixture data or stubs.
