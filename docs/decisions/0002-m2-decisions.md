# 0002 — Decisions made while building M2 (Studio core)

Date: 2026-10-29. No stack changes.

1. **WebSocket contract additions** (all in `packages/shared/src/ws.ts`, marked "M2 addition"):
   `session.start` carries `difficulty` and `drillSection`; `presenter.event` gains `qa_start`; new client message `judge.playback` (TTS started/ended); new server messages `session.state`, `latency.step` (the running stopwatch), `ui.states` (SAM regions for the overlay) and `metric` (server timings for the latency HUD). `ledger.update` carries `segmentStartMs`; `judge.speak` carries `kind` and `trigger`.
2. **Frame header.** Binary frames carry an 8-byte 9x8 dHash before the JPEG (`ws-binary.ts`). The browser hashes each sampled frame and skips unchanged ones (cost control); the server measures screen change from the hash without decoding JPEG.
3. **Speech to text.** Real projects use faster-whisper through the vision service (`WS /stt`, local CPU or Modal GPU). `MODEL_STT` is refused with a clear message until the Meta speech endpoint is confirmed in the docs. Demo Mode uses `ScriptedStt`: an energy VAD detects each utterance and the next line of `demoRehearsalScript` becomes its transcript. It never runs for real projects.
4. **Latency stopwatch without SAM.** With SAM (vision service with `SAM_CHECKPOINT`), an action completes when the spinner or progress bar is gone and a result region appears. Without it, the stopwatch uses dHash distance: a change starts an action, a large change (≥ 6 bits) after it is the result, and the screen must then be stable for 800 ms. Calibrated on synthetic screens; tune `DEFAULT_STOPWATCH` against real demos.
5. **Deterministic verification first.** `auditor/rules.ts` decides what measurements can: speed words ("instant" ≤ 1 s, "fast" ≤ 3 s, "under N s") against the next latency sample within 20 s; numbers need an eval file in the repo (else Unverified plus a Fix Task with a suggested eval script); "encrypt" needs a crypto dependency or code path (else Unverified citing the dependency list). Only inconclusive claims go to the model, and any model verdict without evidence is forced to Unverified.
6. **Interruption policy** (`judges/policy.ts`): only after a final sentence; 45 s per judge; a panel-wide gap of 40/30/20/15/10 s by difficulty 1–5. Difficulty 1 only challenges contradicted claims; 3 adds unverified claims (not features), coverage gaps after half the planned time, and overrun sections; 5 challenges anything. Unverified feature claims wait for show-or-strike (M3). A speed claim waiting for its measurement is not challenged until the measurement decides it. The model only writes the question for a trigger the policy allowed, and its choice is re-checked.
7. **Q&A.** Questions rotate through the panel (the cooldown applies to interruptions only) and wait for the presenter's answer: 1.5 s of quiet after a final. Vague answers (short, or hedged without a number or example) get a follow-up at difficulty 2+.
8. **Yielding.** A judge yields when the presenter says "let me finish" (or similar), presses Cmd+., or talks over it for 1.5 s (server-side VAD). The question is queued and re-asked at the next pause. Use headphones: browser TTS through speakers can be heard by the mic.
9. **TTS** is the browser's `speechSynthesis` with a fixed preset (stock voice, pitch, rate) per persona. No voice cloning.
10. **Session score** (until the M5 take score exists): 60 × average criteria coverage + 40 × claim health, where claim health = 1 − (contradicted + 0.4 × unverified + 0.6 × not shown) / claims.
11. **Coverage** is keyword overlap plus a small synonym list per criteria family (impact, technical, experience, originality, business), so it stays live without a model call per sentence.
12. **Reconnect.** The browser buffers what it sends while disconnected (up to ~100 s) and flushes on reconnect; the server keeps the session for 2 minutes. A session abandoned longer is finalised and persisted.
13. **Recordings** are made locally with MediaRecorder and offered for download. With cloud upload enabled on the project, they go to S3/R2 through `POST /api/uploads/presign` and the session's `recordingUrl` is set.
14. **Job cancellation** is cooperative: `DELETE /api/jobs/:id` removes a waiting job or sets a Redis flag that a running job checks at its next progress update.
15. **Telemetry.** `@stage-ready/ai` wraps every model call in an OpenTelemetry span. Services start the SDK only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set. Cost uses `MODEL_PRICES`; without it cost shows as unknown.
16. **SAM 3.1 adapter** (`services/vision/app/sam_tracker.py`) follows the SAM 3 image API (`Sam3Processor.set_image` / `set_text_prompt`). It could not be run here (no GPU, no checkpoint); confirm the calls against the SAM 3.1 release.
