Date: 2026-11-01. Work from the external review ("Stage Ready (GrillMe) — Review, Score & Improvement Prompt", 49/75), phase by phase. No stack changes. One migration: `0004_m6_guest_demo_attribution.sql` (`users.is_guest`; `model_id` and `model_latency_ms` on `claims`, `judge_turns`, `questions`, `coach_notes`).

## Phase 1 · Judges can try it in one click

1. **Guest Demo Mode.** `POST /api/demo` works signed out: it creates a guest user (`users.is_guest`), sets a signed httpOnly cookie (`sr_guest`, HMAC-SHA256 with `AUTH_SECRET`, 24 h, `SameSite=Lax`, `Secure` in production), seeds Signal Garden for it and redirects. `getCurrentUser()` falls back to the cookie after the GitHub session, so every existing ownership check applies to guests unchanged. Guest creation is rate-limited to 5 per IP per hour; guest users and their projects are deleted 48 h after creation (on the next guest creation). Guests cannot create projects, link repos or turn on cloud upload (`route(..., { guests: "…" })` answers 403 `guest_forbidden` with a sign-in hint); the app shell shows a banner with a Sign in button. DEV_AUTH_BYPASS still wins locally.
2. **No raw JSON on navigations.** `route()` detects browser navigations (`Sec-Fetch-Mode: navigate`, or `Accept: text/html` without fetch metadata): 401 redirects to `/signin`, other errors to `/problem?message=…`, a branded page. `fetch()` callers still get JSON.
3. **Real Meta models in Demo Mode.** `createDemoAi()` wraps the live adapter in `BudgetedLLM`: Demo Mode keeps its scripted speech and fixtures, but claim extraction and verification, judge turns, show-or-strike, Coach Notes and the question bank run on Muse Spark and Muse Wonder. Spend is shared across web, realtime and the worker through Redis (`demo-ai:calls:<day>`, `demo-ai:usd:<day>`, UTC days). Real calls stop for the day at `DEMO_DAILY_CALL_LIMIT` (default 1500, always enforced) or `DEMO_DAILY_BUDGET_USD` (default 5, only for models priced in `MODEL_PRICES`, since Meta's prices are not in the repo); then the prompt's mock answers and the result carries `fallback: "budget"`. A failed real call also falls back to the mock (`fallback: "error"`), so a demo never breaks in front of a judge. `DEMO_LIVE_MODELS` defaults to true in production and false elsewhere, so local runs and CI stay deterministic. Muse Image card art stays off in Demo Mode (fixture renders stay reproducible), as does hosted SAM (DemoGuard's Demo Mode scenario relies on the local tracker).
4. **Model attribution.** `ledger.update` and `judge.speak` carry `model: { modelId, latencyMs, fallback? }`; claims, judge turns, questions and Coach Notes store `model_id` and `model_latency_ms`. Captions read "Muse Spark 1.3 · 1.9 s", "Mocked", or "Mocked · today's demo allowance is used up" (`modelCaption` in `packages/shared`). A claim's caption names the model behind its current verdict: extraction, or the later verification or show-or-strike call; deterministic rule verdicts keep the extraction caption, and their evidence shows the rule.
5. **Brand.** The review's icon set: `src/app/icon.svg`, `favicon.ico`, `apple-icon.png`, `manifest.ts`, `public/icon-192.png` and `icon-512.png`, and `StageReadyMark` replacing the Sparkles tile on the landing page, the sidebar, the sign-in page, the problem page and the cold-start page.
6. **Sign-in page.** `/signin` (Auth.js `pages.signIn` and `pages.error`): the mark, the tagline, Continue with GitHub, "Read-only repo access; Stage Ready never writes to your repo", and Try the guest demo. `callbackUrl` must be a same-site path.
7. **Landing clip.** The review asked for a clip rendered with the Director from the Demo Mode project, but Demo Mode's fixture takes are labelled colour bars, which show nothing of the product. The clip is instead recorded from the real app in Demo Mode by `pnpm --filter @stage-ready/web clip` (Playwright per scene, then FFmpeg: trim, burned captions, 0.4 s crossfades): one click into the demo, a rehearsal where the Claim Auditor contradicts "instant", the Q&A Kit, the Director and DemoGuard. 19.4 s, 1280×720, 380 KB, with a poster frame; it autoplays muted and loops in the hero.
8. **Cold start.** The router answers browsers with a branded "Waking up Stage Ready…" page (503, refreshes every 5 s, light and dark) and API callers with JSON 503 and `Retry-After`. `start.sh` opens the public port only once web and realtime answer, so Modal, which waits for the port, holds the first request instead of showing that page at all in most cold starts. `KEEP_WARM=1 modal deploy …` sets `min_containers=1`.

Tests: guest cookie signing (web unit), the demo allowance and `createDemoAi` (ai), captions (shared), model tags on live messages (realtime), and `e2e/guest.spec.ts` on a second dev server without the auth bypass (signed-out landing → Signal Garden under 10 s with the banner and no JSON; guest limits; branded sign-in; problem page; icons and manifest). The rehearsal e2e checks each judge line and claim chip has a caption.
