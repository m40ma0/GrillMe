# 0008: V2 review fixes

The V2 review (31 Oct 2026, 55 / 75) found the code ready but the live site slow and partly broken. This record covers the 15 tasks in its build prompt: what changed and what could not be done from the repo.

## P0: live site broken or slow

1. **Fast guest seed.** `buildDemoRows` (packages/db/src/seed.ts) builds every Demo Mode row in memory with pre-generated uuid v7 ids. Scoring, audit facts (`auditFactsFrom`, now pure, in facts.ts) and the question bank all run before the transaction opens. `seedDemoProject` then writes one delete and one insert per table: 25 statements, down from about 120. A pg-proxy test counts them. `/api/demo` sends a returning guest straight to their existing Demo Mode project without seeding again and without using up the guest allowance.
2. **Database distance.** `deploy/modal/stage_ready.py` reads `MODAL_REGION` at deploy time and passes it as `region=`. It is unset by default because the repo cannot tell where the Postgres host is. docs/deploy.md maps Neon regions to Modal regions and gives a `curl` timing check. The web pool is explicitly `max: 10`; postgres-js never closes idle connections, so they stay warm.
3. **Storage errors.** S3 failures in web (`StorageUnavailable`, a 503 `ApiError`) and in the worker (`StorageUnavailable`, a `UserFacingError`) now show "Storage is unavailable right now. Your project data is safe; try again in a minute." The raw error is logged, and `storageFailure` in packages/shared classifies it. If a render fails because the renderer was refused an upload, it is reported the same way. `GET /api/health/storage` sends HeadBucket (cached 30 s) and returns 503 `{"ok":false,"reason":"credentials"}` for bad keys. The router's new `GET /healthz` combines web, realtime and storage health. HeadBucket replaces the review's "HEAD on a known key" because it needs no fixture object.
4. **Demo Mode fallback clip.** `apps/web/public/demo/fallback-golden-run.mp4` is 60 s and 0.33 MB, H.264 at preset veryfast and CRF 30. It is recorded from `apps/web/scripts/golden-run.html`, a scripted pass through the fictional Signal Garden app, with `pnpm --filter @stage-ready/web fallback-clip`. Each step lasts 12 s, so the clip matches `demoSteps`' in-points. The Stage page passes this clip in Demo Mode without touching S3. The status line reads "ready" once the clip can play, and "Load the golden-run file" when no clip is loaded. `DEMO_FALLBACK_CLIP` now names the public path.
5. **Env parsing.** `clean` replaces `empty` for every field: it trims, drops a trailing `\r`, strips one pair of matching quotes, strips an unquoted ` # comment`, and treats an empty string as unset. `parseEnv` also cleans the whole source first and names any key it changed on stderr, never the value. `pnpm env:check <file>` checks a dotenv file against every schema in production mode. Production-only rules (placeholder secrets, `ws://`, localhost origins) are warnings, so `.env.example` passes; `--strict` makes them errors.
6. **Fail-fast boot.** `start.sh` sends each service's output to the container log and to `/tmp/stage-ready-logs/<service>.log`. While it waits for health, it checks every child with `kill -0`. If one has exited, it prints that service's last 50 log lines and exits 1 straight away. The health probe uses only bash `/dev/tcp`, because the image has no curl. In a simulated crash the script exited within 1 s.

## P1: judge experience

7. **Guest limits in Redis.** `rateLimit` is now a fixed-window counter in Redis (INCR plus PEXPIRE) that every process shares and that survives restarts. If Redis does not answer within 1 s, it falls back to an in-process count. The guest limit is `GUEST_LIMIT_PER_HOUR` (default 30). The Demo Mode allowance already used daily Redis keys (`demo-ai:*:<date>`), so it did not change.
8. **Instant feedback.** Every "Try Demo Mode" button is now a link to `/demo/starting`. That static page paints the mark and a progress list straight away, then POSTs `/api/demo` with `accept: application/json` (the route now answers `{ projectId, location }`) and navigates to the project. On an error it shows Try again. Without JavaScript, a `<noscript>` form still posts.
9. **KEEP_WARM and prices.** `KEEP_WARM` now defaults to on, and `KEEP_WARM=0` turns it off after judging. Meta's published token prices (dev.meta.ai/docs/pricing-rate-limits, checked 2026-10-31) are built in as `DEFAULT_MODEL_PRICES`: Muse Spark at $1.25 in and $4.25 out, and Muse Wonder at $4 in and $20 out, per 1M tokens. `MODEL_PRICES` now overrides or adds to them. Cached input is billed at the full input price, so costs err high. The dollar cap therefore applies with no secret change.
10. **Studio tracker label.** `expectedTracker` (apps/web/src/lib/server/vision.ts) decides the tracker the same way the realtime server does: hosted SAM 3.1, then the vision service's SAM, then hashes. The rehearse page passes the result in, so the label is right before the session starts.
11. **Freeze while Recovering.** `dgReduce` accepts freeze from `recovering`. The state stays `frozen` with `fallbackSinceMs` still counting, and ticks no longer cut back at the step boundary. Resume goes through `toLive`, which switches back to live and records the fallback time. The Stage window holds the paused clip while frozen this way (`holdClip` in the cue message).

## P2: Meta tooling depth

12. **Muse Voice Transcribe.** `MuseVoiceTranscriber` (packages/ai/src/voice.ts) sends WAV to `POST /v1/asr/transcribe` in `ENDPOINTING` mode, in chunks of 9.5 minutes or less. The realtime server already receives the microphone as 16 kHz PCM16, so it keeps that audio for real rehearsals (`AudioRecorder`; gaps become silence, capped at 40 minutes). After the summary is sent, `finalizeTranscript` replaces the live faster-whisper segments with Muse's turns. Claims and judge answers are re-pointed to the turn they overlap most. The session-review job is queued only after this finishes. The transcript tab now has a caption: "Transcript: Muse Voice Transcribe · x s", "live captions … is refining it", or "live captions (faster-whisper) · <why>". Live captions stay on faster-whisper. Set `MODEL_TRANSCRIBE=none` to turn it off. Demo Mode speech is scripted, so it is never sent.
13. **Visible Muse Image.** Evidence slides get a Muse Image background behind a dark scrim, with "Image: Muse Image 1.0" in the footer. Numbers are still drawn by the renderer and checked by Muse Spark. Muse Image is now also on in Demo Mode for slides and Director title cards. Demo Mode art is cached under one shared key (`demo/slides/…`, `demo/renders/…`), so it is generated once for every guest.

## P3: accuracy and cleanup

14. **README.** Removed the demo-video placeholder. The Meta table is now ordered by what judges see (SAM, Spark, Wonder, Voice, Image) and has the two new rows. The wording no longer quotes the "Mocked" caption.
15. **Test data.** `pnpm db:cleanup [--dry-run]` deletes guests past the 48 h retention (`deleteExpiredGuests`, which `createGuest` now calls too) and every project named "Review test (delete me)".

## Not done, or not checkable from the repo

- **Storage secret.** The bad S3 key in the `stage-ready-app` Modal secret needs the owner. The code now reports it clearly.
- **Region.** No `MODAL_REGION` value is set, because the database host isn't in the repo. The acceptance check (p50 under 400 ms) needs a deploy with the right region.
- **Screenshots and landing clip (14).** `docs/images/*.png` and `apps/web/public/clip.mp4` still show mocked captions and the dev-bypass footer. They must be retaken from the live guest demo (`pnpm --filter @stage-ready/web screenshots` / `clip` with `CLIP_BASE_URL`) once storage is fixed. The acceptance `grep` also matches older decision records that describe the "Mocked" caption; those are history and stay unchanged.
- **Demo video.** No recording exists yet, so the line was removed rather than linked.
- **`/images/edits` cover (13).** Not built. Slides have no product screenshot to place, and the generated background already makes Muse Image visible.
- **Live acceptance checks.** These need the deployed site: under 8 s seed, p50 under 400 ms, the Muse transcript caption with a real key, and dollar figures. Locally there was no Postgres or Docker, so the seed was checked with the statement-count test and a foreign-key order check against the schema, not against a live database.
- **Per-image and per-hour costs.** Muse Image ($0.01 an image), SAM 3.1 ($2.50 per 1,000 images) and Muse Voice Transcribe ($0.18 an hour) are not counted in session cost, which is token-based.
